# 企业反馈整改与验证计划

更新日期：2026-09-23。本文区分**已完成的能力**与**仍待卖家、平台提供的数据**；当前没有真实卖家访谈、授权账单或已获批的 TikTok / 妙手 ERP 接口权限，不声称计算结果已通过真实账单验证。用户称“Easyboss”的粘贴文本对应域名 `91miaoshou.com` 和“妙手开放平台”，若另指 Easyboss 系统需另行确认。

## 直接回答三个问题

### 1. TikTok 关键接口权限申请失败，项目如何继续？

主路径改为“单品手动测算”：打开 `/quick`，输入同币种售价、采购与物流成本、店铺实际费率、退货率、活动折扣和预计销量，服务端确定性引擎立即返回单件及总利润、成本明细。该流程无需平台或 ERP 授权，不把 AI 解析作为必经步骤。已有商品管理和规则解析仍可用于演示及后续扩展；批量导入、店铺同步须在数据权限和字段样本明确后再做。

妙手 ERP 可以是卖家授权后的辅助数据通道，但不能代替卖家确认采购价、实际物流合同、退货损耗、活动专属费率。也不能将“ERP 已有店铺数据”推断为“自动获得 TikTok 活动权限”。

### 2. 真实费率从哪里获取？

按证据优先级取数，并记录**平台 / 站点 / 类目 / 店铺 / 生效日期 / 来源链接或脱敏截图 / 录入人 / 复核日期**：

1. 卖家自己的 Seller Center 费率页、活动报名页、服务协议及适用通知，用于报名时的前瞻费率。费率变化时重新核对，不把演示值当正式值。
2. 卖家导出的结算单和费用明细，用于验证实际扣费、退款和补贴。TikTok Shop 官方文档说明结算报告包含订单级收入、费用和调整项，可从 Seller Center 财务页面导出：[How to Access Your Settlement Report](https://seller-us.tiktok.com/university/essay?knowledge_id=2336057241700098)。
3. 卖家采购台账、物流商发票、支付及换汇记录，补足平台没有的内部成本。退货率采用同店铺、同类目、近 30–90 天可结算订单的退货样本，并注明样本数；新商品样本不足时做情景区间。
4. 官方公开规则只作候选与变更提示，最终以适用于卖家店铺的当前条款为准。TikTok Shop 卖家条款明确费用可能调整，并通过 Seller Center 或邮件通知：[Seller Terms of Service](https://seller-us.tiktok.com/university/essay?knowledge_id=1331308753078058)。

系统现有 `DEMO DEFAULT` 费率仅供演示。`/quick` 不预填真实费率，要求填写费率来源与日期；录入者须确认输入，结果保留“预测”提示。当前未建自动更新的费率库；费率版本、审核和过期提醒列为获得样本后的下一阶段工作。

### 3. 用什么真实数据证明利润准确？

先用已结算且退款窗口基本结束的卖家订单，取得授权后的脱敏原始资料：订单/结算明细、退款明细、商品采购台账、物流与包装成本、活动收费与补贴记录。每笔记录应能以匿名订单 ID + SKU 关联；不采集买家姓名、地址、电话。计算前冻结费率和成本版本，计算后与卖家的独立 Excel 或财务核算表逐项对账。

对账必须区分两个目标：**确定性公式是否正确**，用相同的真实输入核对每个费用项和单件利润；**活动前预测是否有效**，比较预测销量、退货率与事后结果。不能把预测销量误差称为利润公式错误，也不能用演示数据声称通过了实账验证。

建议首批 3–5 位卖家、每位 20–50 笔已结算订单，覆盖盈利、低利润、亏损及退款案例。验收指标预先约定：在费项口径一致、币种和舍入一致的样本中，单项费用和订单利润差异绝对值不超过 0.01 计价币种；无法映射的账单项单列，不强行判为通过。活动级预测另报绝对误差及原因。输出匿名样本清单、字段映射、差异表、访谈纪要和卖家复核签字/确认记录。**这些目标是拟定验收标准，不是已经取得的结果。**

## 妙手 ERP 接口可用性清单

用户粘贴的文本仅覆盖域名、应用注册、签名和错误码，因此此前缺少业务接口页。现已查到[妙手开放平台完整公开接口索引](https://qrzmpphmpd.apifox.cn/llms.txt)，其中包括[店铺列表](https://qrzmpphmpd.apifox.cn/492780418e0.md)、[商品 SKU 列表](https://qrzmpphmpd.apifox.cn/492780582e0.md)、[采购单列表](https://qrzmpphmpd.apifox.cn/492780567e0.md)、[包裹列表](https://qrzmpphmpd.apifox.cn/492780556e0.md)和[退货退款列表](https://qrzmpphmpd.apifox.cn/492780545e0.md)。文档显示包裹响应可含订单金额、平台佣金、实际运费，采购单/商品 SKU 可含采购价格，售后可含退款金额；**这些字段是否覆盖该卖家站点、是否与最终结算一致仍需授权样本验证**。公开索引未见独立的 TikTok 活动报名规则或完整结算费用明细接口，不能据此宣称可自动取到全部利润项。

接入前需要平台文档与真实授权：

| 需要的资料 | 用途与核对点 |
| --- | --- |
| 已审核应用的 AppKey/AppSecret、白名单出口 IP | 仅服务端密钥管理；时间同步；生产环境不得放入浏览器、Git 或文档 |
| 对应业务接口的应用权限与真实响应样本 | 核对公开文档所列路径、字段在卖家账号下是否可用，以及 SKU/包裹/退款映射 |
| 测试账户和最小权限范围 | 验证店铺与 SKU 映射，确认是否有费用及活动字段，不越权推断 |
| 平台授权和卖家同意 | 明确数据控制、存储期限、撤销方式及可导出数据范围 |

签名规则按所给文档为 `HMAC-SHA256(AppSecret, AppSecret + path + timestamp_seconds + bodyJson + AppSecret)`，输出小写 hex；`path` 只用路径，不能带域名或 query，签名的 `bodyJson` 必须与实际发送的原始 JSON 字节一致，空 Body 用空串。签名时效 5 分钟；请求头为 `x-app-key`、`x-timestamp`、`x-sign`。仅 POST、`application/json`。遇到 `appNoPermission`、`ipNotInWhitelist`、限流、签名过期等错误，保留手动测算路径，不静默填入演示费率。

下一步需要已审核应用、卖家授权、对应接口权限及脱敏样本。先做只读映射和对账，再设计增量同步、重试和安全控制；费用项缺口仍以 TikTok Seller Center 结算报告补齐。

## 卖家访谈与核账记录模板

每位受访者记录：匿名编号、平台及站点、商品类目、月活动次数、现用 Excel/ERP 流程、报名决策耗时、最易漏算的费项、可接受输入量、是否愿意再次使用、授权的数据范围。对“愿意付费”只记录原话及价格区间，不推算市场总体比例。

每次对账记录：样本 ID、订单/活动日期、SKU、币种、费用版本、预测输入快照、账单来源、账单费用项、模型费用项、差额、差额原因、复核人、复核时间。差异原因至少区分退款时点、促销补贴、税费、四舍五入、币种换算和费用归属；发现引擎公式问题时加入回归测试并重新跑完整样本。

## 与 Excel、ERP 的可验证差异

当前项目已提供事前单件利润及盈亏平衡、成本拆解和情景分析；Excel 完全可以实现同样的基础计算，ERP 也可能很快加入同类功能。要证明实际优势，需在访谈和 A/B 任务中记录同一卖家使用原流程与本项目完成一次活动决策的时间、漏项数、输入负担和复核差异。费率版本维护及真实场景积累在验证前只能称为建设方向，不能称为既有壁垒。
